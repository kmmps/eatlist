Eatlist · Product Foundations

01

A personal archive of places worth remembering.

01

Mission

Eatlist is a personal archive of places worth remembering. Not a discovery platform, not a review site, not a social feed — a quiet, opinionated tool for people who care about where they eat and want to hold onto why it mattered.

The product exists to help people save, organise, remember, and occasionally share restaurants — with the same care they'd give to a notebook they carry everywhere.

02

Product Principles

Archive, don't overwhelm. The app stores memory, not noise. Every element earns its place.

Personal by default. Eatlist is for you first. Sharing is an option, not the point.

Quiet UI, expressive brand. The product interface stays calm. Brand expression lives in illustration, empty states, and moments between interactions.

Clarity over decoration. Functional elements are never decorative. Decorative elements are never functional.

Memory, not discovery. Eatlist doesn't suggest where to go. It helps you remember where you've been and where you mean to go.

03

Brand Expression vs Product UI

Eatlist has two registers. They must be kept distinct.

Brand world

Campaigns · Landing pages · Social · Posters

  • ✦ Editorial type pairings
  • ✦ Handwritten / script accents
  • ✦ Photo collage, film grain
  • ✦ Bold graphic illustration
  • ✦ Can be loud and expressive

Product UI

App screens · Flows · Components

  • → Handwritten fonts: never for UI text
  • → Illustration: empty states only
  • → Photography: personal, not styled
  • → Fraunces for display only
  • → Inter for all body and UI text

The rule: if a user needs to read it to use the app, it must be in Inter. If it's a moment of brand expression, it can reach for Fraunces or illustration.

Do
  • Use 1px border for elevation (not shadow)
  • White or cream card backgrounds only
  • Max 3 visible metadata fields
  • Minimum 8px gap between list items
Don't
  • Add drop shadows to list cards
  • Use coloured card backgrounds
  • Style cards like social feed posts
  • Compress cards to show more content

13

Iconography

1.5–2px stroke, slightly rounded caps — consistent with the logomark line weight.

Recommended libraries: Phosphor Icons (regular) or Lucide Icons. Pick one, use it consistently.

Do
  • Use outline icons throughout — consistent weight
  • Pair icons with labels in navigation
  • Use logomark for brand moments only (splash, empty states)
  • 24px standard · 20px compact · 16px inline
Don't
  • Mix filled and outline styles in the same view
  • Use food icons (fork, knife, plate) for navigation
  • Use emoji as functional UI icons
  • Use the logomark in tab bars or buttons
14

Photography

Photography in Eatlist should feel like personal memory — a film photo taken at a table, a street-level shot of a door. Imperfect framing is not a failure. It's authenticity.

Not this: overhead food styling, sponsored hero images, stock photography, garnished plating.
This: warm, filmic, natural light, slightly underexposed, B&W acceptable and encouraged.

--ease-inout: cubic-bezier(0.4, 0.0, 0.2, 1.0)  /* position changes */
Do
  • Fade + translate over scale for content transitions
  • Always include prefers-reduced-motion fallback
  • Keep motion invisible to users not looking for it
Don't
  • Use spring or bounce physics
  • Animate more than 2 elements simultaneously
  • Use motion as the sole indicator of state change
17

Focus States and Accessibility

Focus ring

Focused element
outline: 3px solid var(--color-ink);
outline-offset: 2px;

Touch targets

Minimum 44×44px on all interactive elements. Preferred 48×48px for primary actions.

Accessibility checklist (per feature)

  • Focus ring visible on all interactive elements
  • Touch targets ≥ 44×44px
  • Colour contrast AA minimum verified
  • Alt text on all images
  • Semantic HTML (headings, landmarks, buttons not divs)
  • prefers-reduced-motion respected
  • Keyboard navigation tested end-to-end
  • Status never communicated by colour alone

Tone of Voice

Eatlist speaks like a knowledgeable friend who keeps a personal notebook. Warm but not gushing. Precise but not clinical. A little literary.

Examples

Empty state
Do
"Nothing saved yet. Start with a place you keep meaning to go back to."
Don't
"Your list is empty! Add some restaurants 🍽️"
Save confirmation
Do
"Saved."
Don't
"🎉 Added to your list!"
Error
Do
"Couldn't save this. Try again."
Don't
"Uh oh! Something went wrong."
Onboarding
Do
"Your list lives here. Add a place, leave a note, remember why it mattered."
Don't
"Welcome to Eatlist! Let's get started 🎉"

20

Do / Don't

Do
  • Design for daily use — every interaction should feel effortless
  • Use Fraunces for display moments, Inter for everything functional
  • Let user photography be the hero — keep the UI out of the way
  • Apply illustration only to empty states and onboarding
  • Use cream as the base — it's the parchment of a personal archive
  • Treat every card as a memory, not a data row
  • Keep the accent rare and meaningful — one standout per screen
  • Use 1px borders over shadows for elevation
  • Write copy that respects the user's intelligence
Don't
  • Use delivery-app conventions (order CTAs, star ratings, promo banners)
  • Apply handwritten fonts to any functional UI text
  • Introduce social mechanics without deep product consideration
  • Use overhead food photography clichés
  • Animate for delight without functional purpose
  • Use generic food iconography in navigation
  • Add noise to screens that need silence
  • Communicate state through colour alone

Key rules for Claude Code sessions

  • Reference tokens by variable — never hard-code #050615, always var(--color-ink)
  • Start with mobile layout, adapt upward
  • Fraunces for display only — when unsure, default to Inter
  • Notes textareas use Fraunces — the only Inter exception in forms
  • Cards use border (not box-shadow) for elevation
  • No food icons in navigation — use generic place/map/bookmark icons
  • Minimum 44×44px touch targets on all interactive elements
